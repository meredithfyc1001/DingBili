# DingBili 工程架构提案

**决策建议**　采用一个浏览器用户脚本入口、一个生命周期控制器、两类适配器。首个站点实现为 Bilibili，首选主题为 DingTalk。保留原站播放、登录和提交的所有权；主题只接收规范化数据与动作。下文是 P1 设计输入，当前仓库仍是单文件。行号均指 [上游固定版本 bilishu.user.js](../upstream/bilishu.user.js)。

## 布局和依赖方向

```text
DingBili.user.js（唯一分发文件）
  └─ userscript/main → core/runtime、registry、preferences
                         ├─ Site Adapter → Bilibili DOM / open shadow root / 原生动作
                         ├─ 会话模型 → 视频、评论线程、本地同事记录
                         └─ Theme Adapter → IM 壳、设计变量、图标和可用控件
UI 发出用户意图 → runtime 核对页面与能力 → Site Adapter 或本地会话 → 更新 UI
```

## 两类适配器的契约

| 接口 | 输入 → 输出 | 所有权、失败语义与证据 |
|---|---|---|
| Site.match / resolveRoute | URL → 站点或空；路由 → `home / channel / search / video / unsupported` 加原始 URL、内容 ID、来源会话 | 明确保留视频分 P 与时间查询参数，分开帖子 ID 和播放目标；上游 L1026–1035、1093–1096 会将卡片链接重建为仅含 ID 的 URL。 |
| Site.read / observe | 一个活跃路由及其容器 → 数据快照、增量变化、释放函数 | 返回 `loading / ready / empty / unavailable` 及原因。以容器、数据类型划分观察范围，只读自己以外的站点节点。上游 L9860–9882 只更新部分字段，L9961–9975 遇空批次直接返回。 |
| Site.capabilities / act | 原生能力状态；用户意图与目标 ID → `confirmed / pending / unavailable / nativeFallback` | 暴露“当前视频点赞”“进入个人空间”“原生回复”等具体能力。一次点击至多委托一次；提交由原站控件负责，从 DOM 确认状态。原因示例为宿主未就绪、目标已离开、原站要求登录。上游 L8528–8569、8805–8822、9188–9205。 |
| Site.borrowPlayer / borrowEditor | 路由、内容身份、挂载位 → 限定作用域的原生节点借用或不可用原因 | 先记录 anchor、父节点、兄弟、改动属性与原值、焦点，再移动。release 仅归还自己借出的节点或清理失效借用。上游 L1358–1372、1454–1469、8748–8784。 |
| Theme.mount / update / unmount | 主题配置、只读模型、动作分发、由壳拥有的节点 → 视图与释放函数 | 主题不得查询宿主页面、请求数据、解析评论或自行改 History。静态 SVG 与图标属于受控资产；正文用文本节点，URL 按动作验证。上游 L172–177、9324–9329、9775–9825 显示现有字符串模板的边界。 |
| LocalConversation.open / send | 预设会话 ID、纯文本 → 本地记录与未读变化 | 与 Site.act 解耦。维持已有每会话 100 条、每条 5000 UTF-16 码元上限。P1 默认内存留存；持久化、自动回复或跨设备同步须单独定义。L1619–1625、1675–1689、11200–11208。 |

领域对象建议保留 `siteId`、`routeKey`、`revision`；视频包含 `contentId`、原始 `targetUrl`、标题、作者、媒体封面、可选统计；账号仅含页面可见名、头像和允许的原生链接。评论包含站点评论 ID（如有）、页面内临时 ID、根 ID、可选父 ID、正文、媒体和回复计数的“已知/下限”标记。缺少真实父 ID 时只展示原文中的“回复某人”；重名时不推断唯一父楼。未读数缺失与真实零值分开。证据见 L1046–1106、1114–1124、8414–8435、8475–8516、11111–11127。模型是提案，现行脚本使用松散对象。

## 生命周期与恢复顺序

1. **识别页面。** 在 `document-start` 注册一次导航观察。区分站点不匹配、站点内不支持、站点内支持三种结果。等关键宿主就绪再遮盖原页面，挂载失败时提供可操作的原版入口。依据 L8169–8173、11428–11447、11538–11575。
2. **建立路由会话。** URL、关键容器身份或用户切换原版发生变化时，增加世代号并取消旧任务。签名包括分 P/搜索参数；相同 URL 且宿主替换也会更新借用。忽略上一代的异步结果。依据 L8457–8466、8550–8559、8772、10837–10848。
3. **增量同步。** 宿主变化合入一帧，按卡片/线程 ID 更新增删改和顺序；原生节点重渲染时使旧动作句柄失效。仅在用户展开线程时观察该根，保留手工重试。依据 L8604–8629、9831–9882、9961–9992、11553–11575。
4. **先还原宿主，再拆壳。** 停止观察、取消未完成任务，归还编辑器和播放器，撤销自己设置的 inert、标题、favicon、根标记和 CSS 变量，释放视图并恢复适当焦点。站点在挂载期间主动更新的值应保留。全局 History 包装仅在仍由本实例拥有时解除。依据 L8303–8339、8389–8399、8748–8765、11363–11427。对 bfcache 的 pagehide/pageshow 做幂等挂起和重建。
5. **切换主题。** 保留 SiteSession、当前视频、打开的楼层和本地会话，在壳层重绘并重新连接借用槽。P1 可先保持重载行为作为过渡，但验收必须记录会话保留范围；原版逃生始终可用。依据 L1619–1625、11297–11316、11344–11361。

## 首个版本的设计取舍

- 推荐所有新 origin 默认使用钉钉，保持 `@grant none`；偏好只读取本产品列出的键。迁移旧偏好时要区分用户显式选择与上游缺省飞书值，并保留用户原有 BiliShu 设置。www 和 search 的自选主题在此权限模型下各自保存；若评审要求“任意选择自动跨域同步”，需另审共享存储权限或有限枚举传递协议。依据 L7–12、255–262、545–559、1135–1141。
- 首版用 Bilibili 和一个**仅测试使用的内存站点实现**验证接口。将来接第二个现实网站只需注册新的 Site Adapter；把已有三套主题作为切换验证对象。首版没有开发真实第二站或接入钉钉服务的依赖。
- 将样式分为真实主题、共享组件、B站宿主覆盖三部分。先抽取现有 CSS 并比对截图和点击，再按可达性移除 X/XHS 残余。通过色彩、图标和栏位配置统一外观，避免域名、B站 DOM 选择器进入主题模块。依据 L8243–8253、9317–9323、10647–10703。
