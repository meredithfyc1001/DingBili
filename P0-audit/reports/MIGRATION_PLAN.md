# 模块化迁移与 P1 验收提案

**建议把 P1 定义为可回归的钉钉版 B站核心浏览链。** 用户能从首页或分区找到视频、搜索、进入详情、使用原生播放器、阅读和回复评论、访问原生账户及返回原站。模拟同事和另外两套皮肤保留作回归样本。第二个真实网站、真实企业 IM 服务、自动对话引擎及跨设备同步均另行立项。本文件只规定开发顺序与检查标准，等待人工评审。

下列 L 是 [固定上游源码](../upstream/bilishu.user.js) 的位置。T/H 的已测范围见 [测试计划](TESTING_PLAN.md)，DM 为 [数据映射](DATA_MAPPING.md) 的离线函数案例。所有「验收」均指未来候选版本应达到的结果。

## 如何保留上游成果

1. **先搬后改。** 将 L212–248、545–573、966–1107 的纯配置/解析、三主题样式与图标放入可导入模块。用固定样本比对原始输出，建立“上游已有行为”和“已知缺陷”两套断言，避免将错链或旧标题固化成目标。
2. **按完整用户旅程切换。** 先接“首页 → 视频 → 返回”，再接“搜索 → 视频”和“评论 → 展开 → 选定回复”。每条旅程只允许一个模块拥有播放器/编辑器。重构某一层失败时可整条退回已验证的原生路线，避免新旧适配器同时监听或同时提交。依据 L1442–1469、8766–8822、9831–9839。
3. **把 UI 皮肤同站点选择器分开。** 共用播放器和评论桥，保留三主题现有布局；只为钉钉补齐产品要求的路径。先标记从 B站路由到达不了的 X/XHS 分支，再以回归测试支持删除；保留原仓库固定快照可供查证。依据 L8246–8253、8342–8348、9847–9851、10647–10703。
4. **分开验收只读、委托、提交。** 公开页面出现编辑器只验收挂载；点对原生按钮仅验收委托。账号登录、收藏和真实公开回复由获得授权的测试人员在合适对象上验收，留目标正确性和站点反馈即可。账户凭据不进入日志、fixture 或报告。依据 L8740–8789、8805–8822、9188–9205。
5. **保留退出通道。** 功能不可用时展示可操作的原生入口。未支持路径、脚本停用、整页重载、SPA 卸载分别验收；不额外留一份修改过的上游文件用于回滚。依据 L11297–11316、11344–11411、11484–11497。

## 评审时需要确定的产品口径

| 决策 | 建议默认值 | 影响与依据 |
|---|---|---|
| “完整钉钉桌面端”按什么验收 | 指定一个桌面版本和目标截图；对导航、会话列表、详情、楼层和账户入口分屏验收 | P0 能测功能和几何尺寸，无官方对照稿。钉钉主侧栏 9 项仅 2 项有路径，需决定保留装饰还是对接哪项 B站动作。见 [功能矩阵](FEATURE_MATRIX.md)。 |
| “视频群聊”与模拟同事 | 先保留按内容分组的视频会话和有界本地聊天；真实公开互动仅在原生评论区 | L1619–1694、9416–9423、11101–11146。跨刷新持久保存、多人实时投递或生成自动回复会改变产品范围与数据保存策略。 |
| 历史消息与原站换批 | 同一视频更新可见字段。若原站虚拟化回收节点，保留本次会话已读消息；主动换批按批次替换，并给出明确来源 | L9857–9882、9925–9932，T02 的“消失”无法独立区分数据删除和虚拟滚动。定义后才可编写可靠断言。 |
| 两个 origin 的偏好 | 共同默认钉钉；P1 首选沿用最小权限、各源各存。若要求用户更改后立即全域同步，单独评审传递方式 | L7–12、546–559、1135–1141。T04 复现，H02 为两域手工预设的抽查。 |
